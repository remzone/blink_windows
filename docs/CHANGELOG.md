# Изменения

## 0.3.0-preview.4

- Новый пользовательский лог показал: Any6 также отклонён New-NetFirewallRule с HRESULT 0x80070057 (`InvalidArgument`), а 0x80131500/CIM 1 были внешними кодами. Предыдущее объяснение не устраняло весь отказ.
- Создание persistent-правила через NetSecurity исключено. Временная защита полного IPv4-профиля устанавливается прямым Windows Filtering Platform API в dynamic session, транзакционно, после готовности транспорта и до OS routes. При отключении или завершении процесса сессия удаляет свои фильтры; наследованные правила старых версий по-прежнему очищаются.
- IPv6-соединения Blink для внешнего VPN/TURN-транспорта, loopback и служебные NDP/DHCPv6 разрешены в собственном sublayer, остальной исходящий IPv6 блокируется. IPv4 и явный dual-stack WG этим фильтром не ограничиваются; правила других firewall-провайдеров не обходятся.
- Новый этап «Включаем временную защиту IPv6», ожидание до 15 секунд с отменой и очисткой запоздалого результата. При ошибке в файл пишутся имя WFP-операции и прямой DWORD-код API. Из CIM ErrorId теперь извлекается внутренний Windows HRESULT для остальных сетевых операций.
- Размеры и offsets WFP-структур проверяются компилятором для x64/x86, включая 32-битные padding/union. ABI layouts адаптированы из MIT WireGuard Windows v1.1.1; лицензия включена в ZIP.
- Переносимые regression/race tests проверяют откат каждой стадии транзакции и обязательное закрытие сессии при ошибке, выбор защиты для полного IPv4, отсутствие NetSecurity rule creation в сетевом скрипте и извлечение Windows-кода из CIM wrapper.

18 ноября 2026 пользователь подтвердил работу приложения и подключения на Windows после перехода на WFP. README и инструкция для новичков обновлены; технические подробности перенесены в отдельное руководство. ZIP дополнены актуальной документацией без изменения EXE/DLL; SHA-256 архивов пересчитан. Отдельная проверка 32-битной ОС и всех протоколов остаётся в плане проверок.

## 0.3.0-preview.3

- Присланный пользователем журнал preview.2 подтвердил: предварительная очистка успешна, ошибка возникает при создании IPv6-фильтра Firewall, после установки адреса, DNS, маршрутов и NRPT.
- В правиле Firewall подсеть `::/0` заменена на документированное ключевое слово `Any6`, явно заданы все сетевые профили и включение правила. MS-FASP ограничивает IPv6-префикс Firewall диапазоном 1..128. Защита от выхода IPv6 в полном IPv4-профиле сохраняется; ошибка её установки по-прежнему останавливает соединение.
- Файловый журнал настройки сети сохраняет CIM-код, внутренний HRESULT, тип/категорию исключения и FullyQualifiedErrorId. Сырые сообщения, команды и реквизиты профилей не экспортируются.
- Уровни сообщений Xray разделены на `vpn.core_warning`, `vpn.core_info` и `vpn.core_error`. Native поле `errorCode:2` обозначает Warning, а не системную ошибку подключения; общий core не изменён.
- Добавлены регрессии полного IPv4 для VPN/TURN, частичной и dual-stack маршрутизации, разбора кодов Firewall и уровней событий ядра. Windows mock-тест исполняет скрипт с безопасными подставными cmdlets без изменения сети.

EXE x64/x86 собираются локально. Успех реального подключения после изменения Firewall ещё не подтверждён на Windows.

## 0.3.0-preview.2

- Автоматический файловый JSONL-журнал: `%APPDATA%\Blink\logs\blink.log`, ротация 1 МиБ и один резервный файл; записи сохраняются сразу, включая неудачный запуск и `--recover`.
- Для очистки NRPT, DNS-кэша, Firewall и собственного адаптера сохраняются отдельные результаты, количество объектов, HRESULT/внутренний HRESULT, CIM-код и идентификаторы ошибок. Произвольный stderr, ключи и ссылки подписок не пишутся.
- Удалены запросы отсутствующих именованных CIM-объектов; пустые списки правил/адресов/маршрутов считаются успешными. DNS-кэш очищается только после удаления правил Blink. Ошибка теперь называет конкретный шаг и HRESULT.
- В «Диагностике» показан путь журнала, ошибка записи и кнопка открытия папки. Инструкция и screenshot обновлены; пакеты x64/x86 заменяют preview.1.

Причина сбоя на конкретном Windows пока не подтверждена. Версия предназначена для воспроизведения и получения файла журнала.

## 0.3.0-preview.1 — диагностика, стабильный релиз не заявлен

- Нерабочие архивы 0.2.x удалены из текущей ветки и локального dist; прежние ссылки отозваны. История Git не переписывалась.
- Импорт больше не заменяет все подписки. Каждый источник имеет собственные профили, revision, срок и ссылку обновления. Независимая VPN-подписка сохраняется при добавлении и обновлении TURN, и наоборот.
- Выбор серверов каждого типа сохраняется через DPAPI и восстанавливается после перезапуска; прежнее состояние мигрирует без удаления сохранившихся профилей.
- Этапы очистки старых правил, драйвера, ядра, TURN и маршрутов отображаются отдельно. После принудительного завершения перед подключением очищаются оставшиеся правила Blink.
- Запуск ограничен 45 секундами, настройка сети — 30, ожидание TURN — 90. Отмена не ждёт заблокированный драйвер; поздний результат очищается отдельно, до разрешения повторного старта.
- Устранена гонка: поздняя ошибка старого туннеля не может отменить новый.
- Диагностика показывает фиксированные события и числовые коды, отчёт можно скопировать. Ключи, URL подписок, адреса серверов и пакеты не экспортируются.

Зависание на целевом Windows ещё не воспроизведено в этой среде. Preview предназначен для получения отчёта и проверки; работа реального подключения не подтверждена.

## 0.2.1

- Исправлен путь, выдававший «Не найден индекс физического интерфейса»: таблица маршрутов читается через Windows IP Helper API вместо разбора PowerShell. Учитываются активность, метрики маршрута/интерфейса, IPv4/IPv6; собственный Blink исключается.
- На главной и в профилях — переключатель «Обычный VPN / TURN» с количеством серверов. На главной виден список серверов; выбор каждой вкладки запоминается в текущем сеансе. При пустой вкладке предлагается добавить профили, подключение другого типа не запускается.
- Подписи используют общее название TURN; технический протокол и данные подписки не изменены.
- 257 локальных SVG-флагов вместо неполного набора; Казахстан больше не заменяется буквами KZ. Распознаются эмодзи и названия стран на русском/английском.
- Ошибка подключения сохраняется под кнопкой; toast не показывает технический префикс Error.
- Добавлены тесты выбора default interface, переключения режимов, пустой вкладки, флага Казахстана и разделения stdout/stderr. Обновлены screenshots и пакеты x64/x86.

Сборка и browser-тесты выполняются на Linux. Реальное Windows/VPN-подключение требует проверки на целевом устройстве; [границы проверки](validation.md).
